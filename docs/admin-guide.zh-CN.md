# Peerlink 管理员手册

[成员手册](member-guide.zh-CN.md) | [English](admin-guide.md) | [完整部署指南](guide.zh-CN.md) | [返回项目首页](../README.zh-CN.md)

本手册面向 Peerlink 管理员，覆盖冷启动、账号审批、项目目录管理、设备处置和日常运维。成员本地项目的路径和 Codex 环境由成员本人管理。

## 1. 登录与管理员账号

团队服务入口为 [https://peerlink.jd.com/](https://peerlink.jd.com/)。管理员和成员使用同一登录页，管理员账号会额外显示用户审批功能。

- 使用用户名和密码登录，不再使用登录 Token。
- 不要把管理员密码、会话 Cookie 或设备凭证写入 Git、聊天或截图。
- 管理员账号不是全员共享账号；每位成员应注册自己的 ERP 用户名。

## 2. 冷启动项目目录

首次使用时，在“云端项目目录”中创建团队已知项目。

1. 填写稳定的项目标识，仅使用字母、数字、下划线或短横线，例如 `ai-outbound`。
2. 填写让成员能识别项目的说明。
3. 点击“新增项目”。管理员创建的项目直接成为 `ACTIVE`。

云端项目只是团队共享标识。每位成员配对自己的电脑后，再将该标识映射到本机绝对路径。不要在项目说明中填写密码、Token 或机密信息。

## 3. 审批成员

新成员提交注册后会显示为 `PENDING`。

- 确认 ERP 身份和加入团队的必要性后点击“批准”。
- 无法确认或不应加入的申请点击“拒绝”。
- 批准只代表允许进入团队 Hub，不代表允许读取任何人的本地项目。

## 4. 审批成员新项目

普通成员可在网页或通过 `peerlink project-propose` 提交新项目。新项目默认为 `PENDING`。

- 检查项目标识是否稳定、说明是否清晰、是否与既有项目重复。
- 批准后项目成为 `ACTIVE`，成员才能上传本机路径映射。
- 拒绝会移除该待审批目录项。

## 5. 设备与路径管理

成员在“我的设备”生成十分钟有效的一次性配对码。设备配对后只保存可撤销的设备凭证，不保存账号密码。

- 成员自己的设备由成员在网页撤销。
- 撤销设备会同时删除该设备的项目路径绑定，并取消未结束任务。
- 云端保存路径元数据用于路由，不上传项目文件。对其他成员查询时不返回本地路径。

## 6. 请求审批边界

管理员身份不代表可以替项目负责人批准任务。只有接收方本人可批准对自己项目的请求；本地 Codex 生成答案后，仍需本人审阅并确认发送。

## 7. 日常检查

```bash
ssh test-198 'systemctl status peerlink-hub --no-pager'
curl -sS https://peerlink.jd.com/health
```

只重启 `peerlink-hub` 服务，不要为 Peerlink 重启现有 `jdme-bot` 容器。数据库为 SQLite WAL；备份时使用 SQLite 在线备份 API，或停止 Peerlink 后备份整套数据文件。详细部署、升级和安全边界见[完整指南](guide.zh-CN.md)。

## 8. 管理员检查清单

- Hub 与 `/health` 可访问。
- 待审批成员均已核实身份。
- 项目目录没有重复标识或敏感信息。
- 待审批项目均已处理。
- 不再使用的设备已撤销。
- 不共享管理员账号，不把凭证写入 Git。
